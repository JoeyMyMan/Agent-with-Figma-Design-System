## Design system (ds-workflow {{version}})

This project's UI comes only from the design system **{{name}}** — source: {{source}}; pinned version in `design-system/lock.json`. Proposals and written-back screens go to Figma file `{{workFile}}`. Before writing pages, components or styles, or doing any Figma task, read `{{playbooksDir}}/README.md`, then the playbook for the task.

**Hard rules**
1. **Visual values are tokens only.** Colours, font sizes, font weights, spacing, radii and shadows are written as `var(--{{prefix}}-*)`, generated by `npx ds-workflow build` into `{{css}}`. Never edit that file by hand and never write colour literals or font names. If the design system lacks a value, propose it in `{{proposed}}` (`playbooks/ds-propose`) instead of hard-coding it.
2. **The component library ({{componentDirs}}) uses tokens only, no px.** One Figma component set = one code component; its variant properties are the props. Pages only compose components and lay them out.
3. **Reuse, then extend, then create.** For every UI element, first look for a design-system component, then add a variant to an existing one, and only then create `{{proposalPrefix}}/<Area>/<Name>`. Record the result in `design-system/components.registry.json` with status reuse / extend / proposed / approved / deprecated.
4. **Write back to Figma with component instances only.** Build frames with the Figma MCP `use_figma`; never HTML-to-design imports or screenshots. Proposals go on the "{{proposalPage}}" page, screens on the "{{screensPage}}" page. If your agent cannot write to Figma, hand the write-back to someone who can (`ds-review-loop`); do not substitute anything else.
5. **Every UI change goes to the designer for review, automatically, and finished screens are never overwritten** (`ds-review-loop`). Sections whose name starts with "{{readyMarker}}" and everything in `{{ledger}}` under `ready` / `unconfirmed` are the designer's: put changes in a v2 beside them, and only add variants to components they use. Remind the designer through the channel the project chose ({{channel}}), mark changed frames "{{pendingMarker}}", and record the batch under `pending`. When a section becomes Ready, align the code to it (`ds-align-ready-for-dev`).
6. **`npx ds-workflow check` must pass before every commit.** If it fails, fix the code. Never update the baseline to pass (`--update` is only for after a migration), never delete checks.
7. **Everything is pinned to a version.** Upgrade the design system through `ds-upgrade`: sync, diff report, migrate, verify. Never edit only the token file.
8. **Shared state lives in the repo, not in an agent.** Pinned version, registry, review ledger and proposals are files in the repo, so every agent and every person sees the same state. Never keep it only in an agent's memory or a chat, and update the files in the same change as the code.
9. **Only people decide.** An agent never marks a proposal approved, a section Ready, or a review done (it only records in the repo what a person decided), and never releases to production while `npx ds-workflow review --strict` fails.

**Commands**: `npx ds-workflow sync …` (sync and pin) · `build` (token CSS) · `check` (gate) · `registry` (render the registry `{{registryMd}}`) · `review` (the review ledger; `--strict` before a production release) · `rules` (refresh this block and the playbook copies)
